## 4. 阶段执行要点（相对 v1 的增量变更）

- **阶段 0** 增加：锚点数据包按 §1 口径采集（含 arena/vision 场景）；磁盘水位检查；multi_turboquant/humming-kernels 在 cp312 下的可用性预检（multi_turboquant 是 py3-none-any，预期无碍）。

- **阶段 2** 变更：每批的三方合并**包含 0.30 同文件 hunk**（A3/A4/A5/A6、D 组相应部分），避免同一文件改两遍。
- **阶段 3** 变更：切换后滚动制，每项独立 commit + 功能验收；砍量按 §0 顺序。**新增铁律**：平台专项类移植（CuTe DSL / DeepGEMM / CUTLASS）**先查依赖在目标 OS 上是否存在**（查包元数据 `Classifier: Operating System`）——步骤 038 的 D4 代码移植精度 100% 却因运行时依赖 Linux-only 白做一轮。
- **阶段 5** 增加：止损或完成后都出交接文档（含"下个 27b 换新底座时可直接复用的资产清单"：锚点脚本、迁移源 diff、验证脚本）。**新增**：改完生产参数后须 `grep` 全仓该参数的旧值，逐个判定「历史记录 vs 现役描述」（步骤 041 因此补出三处遗漏）。

## 5.5 任务 T-perf：decode 性能优化（用户指令立项：**移植完成后执行**）—— ✅ 已收官
