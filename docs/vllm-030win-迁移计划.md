## 5.5 任务 T-perf：decode 性能优化（用户指令立项：**移植完成后执行**）

**起因**（2026-09-25 深夜，步骤 006/007）：用户基准锚 = 无草稿 **57–60 tok/s**（参照 `run_qwen_textonly_offload_200448_stable.cmd`，生产实跑过，改动前水平）；实测复现 55.7 ✓。但带草稿的增益远低于理论：**spec 步长 = 无草稿的 2.2 倍**（17.9ms → 35-39ms），把 1+N×acc 的 token 增益吃光（N=2 仅 +3%，N=3 +16%；用户理论预期 N=2@50% ≈ 90 tok/s）。

**靶子**：spec 步长从 2.2× 压回 ~1.4×（verify 批量 + 5 层草稿前向的合理成本），预期 N=2 → ~83、N=3 → ~100 tok/s（4k）。

**已知线索**（按优先序，步骤 007 已完成关键隔离）：
1. **【已定罪】spec 管线 O(L) 每步开销**：无草稿 100k 步长仅 19.8ms（注意力 KV 读 ~2ms/步接近满带宽，内核无罪），spec 步长随长度线性恶化至 129ms（~0.9µs/token）——每步有随上下文线性增长的慢速访存/扫描类操作（疑点：草稿滑窗块管理驱逐扫描、每步草稿 context KV 写、对齐调度）；**100k 处带草稿比无草稿慢 2.7×**，此乃"溢出感"实体；
2. 短上下文 spec 步长 2.2×（17.9→35-39ms）：propose 便宜（C1 实测 ~7ms），疑 verify 批量前向 / 草稿 KV 写 / 调度对齐；
3. 历史对照：N=3 doc_4k 85.18（复现 83.33）vs N=2 60.65——N 敏感度异常高；
4. 若归因到"很多改动以前"的回退：对 overlay 提交史做 A/B（C1 探针/调度器 computed 修复/GC 冻结等嫌疑）。

**纪律**：优化在迁移切换后执行；迁移期只采集不调优（零容差锚按现状锁定）。

**⭐2026-09-26 更新（切换完成，素材就位）**：0.29 栈同工具跨栈对账——O(L) 开销**仍在但便宜 8-24%**（8k 33 / 32k 50 / 100k 98 ms，斜率 0.98→**0.71 µs/token**）；另发现未解异常：stage0 真实请求口径步长全程平（31-33ms vs 同栈 A5 口径 50-98ms，prompt 实长已核实非伪影，三疑点=会话/请求路径 chat-vs-completions/内容），立项时先分离它——若平步长是真机制，O(L) 优化空间比原估计小。**优先级调整：KV offload 修复（R8，用户 9-26 指示）先于 T-perf**。
