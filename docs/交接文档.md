## 2. 环境契约（跑任何 vllm 前置条件，缺一必炸）

1. **VS 环境**：`call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat"`（torch/humming 现场编译要 cl+ninja）
2. **HOME/USERPROFILE=C:\fi**（humming 缓存键的一部分——不一致会触发重建然后炸）
3. **CUDA_HOME/CUDA_PATH=C:\PROGRA~1\NVIDIA~2\CUDA\v13.3**（**8.3 短路径反斜杠**，正斜杠=缓存键漂移）
4. **LIB 加 CUDA lib\x64 与 Python libs**（链接 cuda.lib/python3.lib）
5. TMP/TEMP 重定向 G 盘（磁盘治理铁律）；zmq 29550 端口残留先清（wrapper 已内置）
6. **完整可跑模板** = `tools/run_anchor_ppl_base029.cmd`（新底座）/ `tools/run_anchor_ppl.cmd`（旧栈）——照抄别重造。

## 3. 已修复/已建（重装环境必重放）

- **humming-windows 0.1.15 八件套**（`tools/shims/SHIMS.md` 索引）：它并未真正移植 Windows（dlfcn.h/sys/mman.h/GNU 旗标/.so 命名照用）。含 mapped_file Win32 移植（NOMINMAX！）、构建旗标治本、nvrtc 定位器、device_info 扩展、nvrtc_compile 移植、launcher 链接。产物缓存 `C:\fi\.humming\cache\`。
- **qwen3_5.py 量化 embedding 2 行**（底座 commit `7bb4ce0`，同 `tools/shims/qwen3_5.py.embed-patched`）。
- **已知缺口（预期内，勿再排查）**：0.29 纯底座**不支持 SM120 的 nvfp4 KV**（注意力后端拒绝）——这是我们 overlay 的自研补丁（批 5），搬完才可用 nvfp4 KV；smoke 用 bf16 KV。

## 4. 锚点体系（验收对照系，判等用 PPL 不用文本）

数据在 `G:\qwen3.8model\vllm-030win-锚点数据包\`（docs/ 有副本）。核心表：
- **PPL 双栈**：`ppl_anchor_overlay0271.json`（锚）vs `ppl_anchor_base029.json`（0.29，|Δ|≤0.0025）
- **无草稿基线** 55.7/54.2/50.3 tok/s（4k/32k/100k）= 用户基准 57-60；**spec N=2** 57.5/34.1/18.9
- **runner 原口径 N=3 doc_4k = 83.33**（85.18 复现，引擎零回退）
- 长上下文锚 = N2 配方去 offload（池 3.6e9 贴合 121,776）+ 热身 1 + 3 重复中位 + usage token 口径
- **测量铁律**：chunk 数≠token 数（按 usage.completion_tokens）；热身弃 1；合成 prompt 压接受率（0.53-0.57 vs 自然 0.65-0.74）；**禁 KV 溢出内存**（测量配置去 offload/prefix-cache 或断言 kv_offload CPU_to_GPU==0）；停服杀进程含 spawn 孤儿+按端口清。
