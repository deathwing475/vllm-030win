# 任务收尾规范 — 每一步做完之后该落地哪些文件、各写什么

> **用途**：一次任务（一个"步骤"）结束时，按本文的清单与颗粒度更新文件。**违反会导致两类事故**：信息错位（下个会话读到过时状态）或上下文膨胀（提示词被细节撑爆，开场就灌满）。
> **来源**：2026-09-30 用户指令「给交接提示词瘦身，该删除的删除，该放其他文档的就放到其他文档，并把收尾规范写成文档」。
> **本文也是要维护的文档**：流程变了就更新它。

---

## 0. 一句话

每次收尾 = **代码/工具改动 → 各文档按各自颗粒度更新 → 同步 venv → 复核自检 → commit + push → 清临时缓存**。

---

## 1. 文件分工与颗粒度（**核心，先读这一节**）

| 文件 | 定位 | 写什么 | **不写什么** | 篇幅 |
|---|---|---|---|---|
| `vllm/`、`tools/` | 交付物 | 代码与工具本身（含 revert 脚本） | — | — |
| `docs/实验步骤文档.md` | **每步四段式**（协议 / 操作 / 结果 / 判定） | 本步要验证什么、实际做了什么、数据、结论与下一步 | 跨步沿革 | 一步一节，**细节主战场，可长** |
| `docs/实验日志.md` | **按日工作流水**（倒序，编号递增） | 做了什么、关键结论、踩坑、运维、下一步 | 与步骤文档重复的四段式 | 一条 6-8 个 bullet |
| `docs/交接提示词.md` | **新会话开场提示词**（要能整段粘给 AI） | 仓库纪律 / 使命 / 当前状态 / 关键机制 / 关键路径 / 必守 / 下一步 | **历次细节、已结案叙述、历史沿革、逐步数据** | **全文 ≤ ~14 KB**；只留"接手必须知道" |
| `docs/交接文档.md` | 接手入口 | 各线**当前状态摘要** + 环境契约 + 未完成清单 | 逐步数据 | 每节 1-2 段摘要 |
| `docs/进度文档.md` | 阶段总览 + 任务板 + 资产地图 | 阶段状态、任务板头名、资产路径、关键数字、下一步顺序 | 逐步数据 | 表格化 |
| `docs/交接收档存档.md` | **历次收档全文**（倒序） | 从提示词里搬出的历次收档块、已结案总览、挂账观察 | — | **无上限（信息不丢）** |
| `docs/vllm-030win-调研-*.md` | 专题设计权威 | 机制设计、决策记录、实测、边界、**未验证项**、风险登记册 | — | 无上限 |
| `README.md` | 仓库门面 + 状态表 | 仓库纪律、迁移战役状态表 | 细节 | 表行 ≤ 1 行 |

**判据**：一份内容该放哪里，问"下个会话**必须**在开场就知道它吗？"——是则进提示词（且压到最短），否则进步骤文档/设计档/存档，提示词里留**指针**。

## 2. 收尾清单（按顺序执行）

1. **代码与工具**：改动落在记录仓 `vllm/` 与 `tools/`；**任何 venv 源码补丁必须有对应 revert 脚本**（必守第 14 条）。
2. **同步 venv**：`python tools/sync_venv.py --write <repo 相对路径>`（**路径相对 `vllm/` 根，不带 `vllm/` 前缀**），它会顺带核全树一致。
3. **步骤文档**：新增 `## 步骤 NNN — <标题>：**<结论一句话>**（日期）` 插到最前（倒序），四段式。**插完必 `grep -n "^## 步骤"` 复核序列**——历史上多次"插入吞掉下一节标题"。
4. **实验日志**：新增 `## <日期>（<编号>）— 步骤 NNN：<一句话>` 插到最前，6-8 bullet。
5. **专题设计档**（若本步改了机制）：新增/更新对应小节（KVMem 线 = §12.x），写机制、实测、**边界（勿误读）**、**未验证项**。
6. **提示词**：只动三处——"当前状态"里本线的一句话、"下一步"的头名、必守（**仅当产生新纪律时**）。**细节一律不往这里写**。
7. **交接文档 / 进度文档**：更新对应线的状态摘要与任务板头名（若本步改变了"当前头名"或某线状态）。
8. **存档**：若从提示词搬出了内容（历次收档、已结案总览、挂账观察），追加到《交接收档存档.md》，**内容零删减**，只把 blockquote 改成一节一标题。
9. **README**：状态表加**一行**（本步一行内写完）。
10. **commit + push**：**一步一 commit**（文档与改动同 commit）；`git push origin main`——**唯一远程仓，禁止只提交本地仓**（必守第 3 条）。
11. **清理**：清临时缓存、查磁盘水位（`df -h /g`）。**注意 `G:\qwen3.8model\_tmp_prod029` 里是生产在用的 8 GiB offload mmap，不可删**。

## 3. 篇幅纪律（防上下文膨胀）

- **提示词是提示词，不是文档**：能指向设计档/步骤文档的，一律**指向**，不复述。
- **已结案的内容从提示词搬到存档**——这是 2026-09-29 用户指令「把各种收档从交接提示词里移出去」的由来。
- 每步只往提示词加"接手必须知道"的部分；**历史沿革进存档**。
- 提示词膨胀到 20 KB 以上时，主动做一次瘦身（把历次细节搬存档）。

## 3.5 记忆索引（MEMORY.md）纪律

`MEMORY.md` 是**每次会话开场就加载进上下文的索引**，有硬上限（~24.4 KB），超了就**只能读到一部分**——2026-09-30 实测它涨到 29.6 KB（119 条、11 条超 500 字符），已触发截断。所以：

1. **MEMORY.md 只放纯目录**：一行一条 = `[标题](topic文件.md) — 一句话 hook（≤ ~100 字符）`，**正文一律不进索引**。
2. **详情写 topic 文件**：新记忆 = 新建/更新 `memory/<slug>.md`（frontmatter + 正文），然后往 `MEMORY.md` 追加**一行**索引。
3. **更新已有记忆时改 topic 文件**，索引行的 hook 只在语义变化时同步改。
4. **索引超限时做一次纯目录化**：用脚本把每条索引行的长描述搬回各自 topic 文件（已存在则末尾追加"来自 MEMORY.md 索引行"一节，信息零删减），再重写索引。2026-09-30 已做过一次（29.6 KB → 18.4 KB，119 条全部搬运，0 个文件缺失；脚本 `_tmp_line_b/slim_memory_index.py`，备份 `MEMORY.md.bak-20260930-slim`）。
5. **允许用脚本搬运记忆文件**（memory 目录不在 git 仓库里，不受"仓库内文件写入走 Write/Edit"约束）；但**搬运必须零删减**，hook 允许直接截断原文而不是手写。
6. **索引开头必须保留「给 AI 的使用规则」块**（2026-09-30 用户指令）：明示"本文件只是目录、详情在 topic 文件、**禁止把目录指向的文件全读一遍**（100+ 个文件全读会把上下文撑爆）、只有直接相关才读、一次最多 2-3 个"。改 MEMORY.md 头部时**不得删掉这个块**。

## 4. 收尾自检清单（做完逐项核）

- [ ] `grep -n "^## 步骤" docs/实验步骤文档.md | head` —— 序列连续、无吞标题
- [ ] `python tools/sync_venv.py --quiet` —— 全树一致（无输出 = 通过）
- [ ] `git status` clean 且与 `origin/main` 同步
- [ ] 提示词 `wc -c` 未显著膨胀（目标 ≤ ~14 KB）
- [ ] 新写/改动的 `.cmd` 行尾为 **CRLF**（`python -c "b=open(p,'rb').read(); print(b.count(b'\r\n'), b.count(b'\n')-b.count(b'\r\n'))"`，第二个数须为 0）
- [ ] 生产未被扰动：若跑过实验臂，已用 `tools/prod_watchdog.ps1` 恢复并核验 8k 快档 + `tools/prod_headroom_check.ps1` 余量判据
- [ ] 复跑锚点用**新文件名**，不覆盖旧证据
