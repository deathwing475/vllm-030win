# 锚点采集协议（阶段 0，2026-09-25 起）

> 目的：迁移验收的对照系。新栈一切达标判定以此为锚（迁移计划 v2 §1：性能总分 **0% 容差**、PPL 逐位、容量不缩水）。
> 数据目录：`G:\qwen3.8model\vllm-030win-锚点数据包\`（脚本输出 JSON + 本协议比对表）。
> **现役栈定义**：overlay 开发头（`vllm-overlay`，tag `freeze-migration-20260925`）+ vllm-win venv——即迁移源本身。生产 site-packages 是旧冻结物，不作锚。

## 1. 口径总则

- 采集协议三段式：**冷启动 × 样本 × 重复**沿用 runner v2 口径（3 冷启动 × 5 样本，median 汇总；warmup 弃 1 条）。
- **稳态按 `usage.completion_tokens` 计**：vLLM 流式每引擎步一个 delta、可含多 token，chunk 数 ≠ token 数（步骤 006 教训）。
- 吞吐/TTFT 以引擎侧流式逐 token 计时为准；`nvidia-smi` utilization 不作判据（有假卡前科）。
- **禁 KV 溢出内存**（用户铁律 2026-09-25）：测量配置去掉 `--enable-prefix-caching`/`--kv-offloading-*`，池值手算贴合 max-model-len；若保留 offload 须断言 `kv_offload CPU_to_GPU == 0`。
- PPL 判等用 mean_nll 六位小数逐位比；跨进程文本非确定，**单条文本不作等价判据**。
- 一切池值手动设置（`--kv-cache-memory-bytes`），各臂同池值；launcher 从带池值配方衍生。
- 停服按命令行杀进程（含 `multiprocessing.spawn` 孤儿——步骤 004 后两次咬人）；每轮收尾清临时缓存（TMP/TEMP/VLLM_CACHE_ROOT 一律重定向 G 盘）。

## 3. 新栈复跑规则

1. 同脚本、同 prompt 集、同参数（PPL 的 meta 必须同 `max_model_len/gpu_mem/enforce_eager/kv_dtype`；prompt_sha256 与 tokenizer_sha256 任一不符即不可比，先归因）。
2. 每项判据按迁移计划 v2 §1；A1 六位小数逐位比，A2–A5 零容差（总分），A6–A8 功能通过即可。
3. 任何回退走兜底流程：归因 → 砍特性 → 重测 → 仍不达标即止损。
