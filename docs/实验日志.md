## 2026-09-26（七）— CPU 派发优化首胜：草稿图化解耦，decode −13.3%（步骤 023）

**做了什么**：①trace 子段归属修正两判断：pin_memory 347µs=prefill 期大块钉页（decode 期 7µs，撤案）；草稿前向每步 ~3.7 次 eager 调用（内含 6×apply_humming+4×grouped_conv）≈3.7ms/步 Python 胶水=头号靶。②**实验 B（阴性）**：splitting_ops 去 GDN 想把它捕进 PIECEWISE 图——32k 输出塌缩（重复风暴=状态/分支冻结错）即回退；记档「GDN 不可简单入图，48 次/步是结构性成本」。③**实验 C（✅）**：定位 `dflash/speculator.py` 把草稿图模式绑死在 target 模式（engine=PIECEWISE ⇒ 草稿全 eager），而草稿的 FULL_DECODE_ONLY 图管理器与 target 图模式无关——**解耦修复**（双轨）；风险天然低（草稿错只掉接受率，verify 兜底正确性）。④验证：草稿图捕获成功（无「不支持」警告）、needle 32k 命中输出连贯、接受率带内、**e2e 31.53→27.29/27.35ms（boot-1/boot-2 同产物复现 ±0.2%）=−13.3%、吞吐 77→89 tok/s（+15.5%）**。

**判定**：**CPU 派发优化战役首胜 ✅**。剩余靶点挂账：GDN 包装张量活减脂（copy_/clone/index_put_ 每调用×48）、attention/kv_update 包装、apply_humming 派发单价、生成码快慢态差。教训：图化对无状态算子安全、对元数据分支算子致命，入图必须过输出正确性门；草稿/验证的正确性分工使图化实验风险不对称——先打风险低的。

**做了什么**：①步骤 018 平步长反常（stage0 31/31/33 vs anchor 33/50/98ms）三疑点分离——单 serve 判别矩阵 18 臂全平（37-47ms），会话/路径/内容三因子全灭，异常=boot 级；两侧工具口径对账（tail≈0、delta=引擎步粒度）排除测量伪影。②按用户观察实测溢出：长 decode 对照（短提示词 36-38ms vs 100k 37-38ms/步，与 L 无关）+ per-process Shared 488MB 全程平线 + 时钟满血 ⇒ **非溢出**，70%/80% util=decode 阶段形态（GPU 空转）。③torch profiler 步内剖：**GPU 内核并集 14.9ms/步贴权重读取地板，每步其余是图外 CPU 派发**（GDN 包装 244µs×48、KV update 329µs×21、attention 226µs×21、CompiledFxGraph 7.5ms/步、apply_humming_linear 每调用 to_str JSON）——spec 理论 2.5× 实拿 1.27×，一半收益被 CPU 吃掉。④to_str 缓存修复（双轨）——A/B 被 boot 方差混淆，如实记「无净效应」。⑤**boot 级方差（25.8/26.8/36.9-44ms 多态）根因定案**：AOT 产物审计揪出 `parallel_state.py` 内联 vs 磁盘恰差 1 字节；微观实验实锤=`inspect.getsource` 对无尾换行文件补 `\n`、`open().read()` 不补 ⇒ AOT 校验每 load 必败 ⇒ 每 boot 重编译 ⇒ inductor 生成码漂移。⑥修复（底座 `3498ef1`，尾换行哈希规范化）：三产物 3/3 `Directly load`、零重编译、启动 60s、**同产物两 boot 步长 30.81/30.70ms（±0.4%）——boot 方差冻结**。

**判定**：**T-perf 首战双结**：溢出排除 + boot 方差根因修复（decode 性能从此可复现，历史「O(L) 异常/平步长」大概率均为生成码方差的产物）。真优化靶点=CPU 派发结构（估 30.7→~20ms 空间），挂账立项。快慢态产物差（25.8 vs 30.8ms）挂账待解剖。教训：①「多改合并后宣称修复」的 Q4 教训实战应用——A/B 被方差混淆就如实写无结论；②审计缺 import 的模块会漏判（compressed_tensors 两个模块首跑漏审）；③Python 注解 `"X" | str` 在 def 求值炸，须整体字符串。
