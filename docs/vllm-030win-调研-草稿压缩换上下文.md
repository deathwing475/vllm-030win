## 1. 命题重述与 043 的关系

043 已收档「0.545 GiB = 接受率 ±1pp 约束下的体积地板」。用户本次**放宽了约束**：接受度允许从现值降到 54%（现值见 §2，65.4%）——043 的「地板」结论在新约束下**失效，需要重算**，且 043 的搜索空间本身有漏项（§3 的 mlp 1bit 维度从未被触碰）。

方向链：压草稿权重 → 省物理显存 → **守恒回填 KV 池值**（E 轨）→ num_blocks 增 → max-model-len 上限上探 → 上下文空间增大。

## 2. 接受度口径校准（关键前提）

三套历史口径必须分开（不可混用）：

| 口径 | 定义 | gptq3c 现值 |
|---|---|---|
| **生产 /metrics（用户 54% 的最自然映射）** | `spec_decode_num_accepted_tokens_total / num_draft_tokens_total` | **65.4%**（046 生产 boot 实测：accepted 581 / draft 888，444 步样本；pos0=77.5%、pos1=53.4%） |

| 旧协议（023/024） | inc2fix 等 | 50.0%（inc2fix） |

- **单点换算锚**：gptq3c B1 0.537 ↔ 生产 65.4%，差 ≈ **+11.7pp**（单点外推，不可靠，阶段 1 实测校准）。
- **生产 54% 门 ≈ B1 0.42**。按此门 gptq2c（0.478）/gptq4c（0.465）名义上都过——**但用户裁定 qkv 不可再压（§3），这两臂已排除，翻案推论作废**；B1 门只用于给新配方（mlp 1bit 等）做初筛。
- **吞吐代价预算**：产出/步 = 1 + pos0 + pos1。现值 2.31；54% 口径（pos0+pos1=1.08）→ 2.08 ⇒ **decode 吞吐 −10%**（8k 122.58→~110；146k 107.73→~97；判据①≥85 ✓②≥70 ✓）。残谱 boot（86.7 级）×0.90 ≈ 78 ⇒ **残谱下 8k 破 85 门**——watchdog 重启兜底 + 探针阈值须重标定（105 → ~100，8k 预期 ~110 余量才不薄）。
- 正确性：spec 的 greedy 验证保证输出 = target，**草稿权重压缩不影响输出正确性**（needle 照跑作冒烟即可），PPL 锚不受影响。

## 3. 草稿权重构成账（gptq3c checkpoint 实测，total 557.8 MiB）

配方（config.json）：默认 **2bit** + qkv_proj/fc **3bit** + hidden_projection **4bit** + kernel_projection **2bit** + 码本 **4bit**。

| 块 | bit | MiB | 占比 | 再压维度 |
|---|---|---|---|---|
| **mlp gate/up/down（5 层 ×3）** | 2bit g128 | **341.7** | **61.3%** | **→1bit 省 171 MiB（043 从未触碰的最大维度）** |
| other：qkv_proj(3bit) ~56.6 + fc(3bit) 46.9 + norm ~5 | 3bit | 109.1 | 19.6% | **qkv 用户裁定不可再压（2026-09-28：「qkv 基本不能量化了，会损失很大部分精度」）⇒ 保持 3bit；fc 连带保守保持 3bit** |
| candidate_selector 码本 ×2 | 4bit | 62.5 | 11.2% | →2bit 省 ~30（043 标「高风险」——码本质量直接打接受率） |
| o_proj | 2bit | 26.8 | 4.8% | →1bit 省 ~13 |
| kernel_projection（conv） | 2bit | 16.9 | 3.0% | →1bit 省 ~8 |
| selector.hidden_projection | 4bit | 0.7 | 0.1% | 忽略 |

**关键发现：043 的「配方内唯一大杠杆 = qkv/fc 3→2bit」路线被用户裁定排除**（qkv 量化精度损失过大；gptq2c/gptq4c 的 B1 掉 6pp 主要就是 qkv/fc 2bit 的代价——与用户判断吻合）。**剩余可压维度 = mlp 1bit（171）+ 码本 2bit（30）+ o_proj/kernel_proj 1bit（22）**。

- **保守上限 ≈ 52 MiB**（码本 2bit 30 + o_proj/kernel_proj 1bit 22；qkv/fc 不动）。
- **激进上限 ≈ 223 MiB**（+ mlp 1bit 171）。
- **557.8 → ~335 MiB（−40%）**，前提 = 1bit 接受率不崩（R1，最大风险）。

## 5. 显存 → 上下文换算表（G=8、ssm bf16、block 1456、bytes_per_block = 13,418,496 B）

`num_blocks = ⌊pool/13,418,496⌋`；`L_max = ⌊(num_blocks−29)/2⌋ × 1456`（mamba 组 24 + sw 4 常数 + null block）。锚点：pool=3.4e9 → 253 → **163,072**（046 生产已验证，公式可信）。

| 情形 | 草稿 MiB | 回填池值 | num_blocks | **L_max** | vs 163,072 |
|---|---|---|---|---|---|
| 现状（046） | 557.8 | 3.4e9 | 253 | **163,072** | — |
| 仅 E 轨（045 bf16 省的 273.1 MiB，未回填） | 557.8 | 3.686e9 | 274 | **177,632** | +14,560（+8.9%） |
| E 轨 + 保守 52（码本 2bit + o_proj/kernel_proj 1bit；qkv/fc 不动） | 505.8 | 3.741e9 | 278 | **180,544** | +17,472（+10.7%） |
| **E 轨 + 激进 223（+ mlp 1bit）** | ~335 | 3.920e9 | 292 | **190,736** | +27,664（+17.0%） |

- 主模型 `max_position_embeddings` 262,144 ≥ 192k，无 rope 外插问题。
- 草稿权重压缩**不直接改变 KV 记账**（草稿 KV 是窗口常数 4 blocks/请求、且「所有 group 每 block 物理内存相同」约束已由 034 定案）——收益全部走「物理守恒 → 池值上探」这一条路。

## 6. 池值上探的机制风险（035 复核）

- 035 定罪「3.4e9 硬上限」的对照（3.4e9 vs 4.6e9）是**非守恒**实验：池值 +1.2e9 时总物理占用暴增 → WDDM 过承诺 → prefill 4.13×。
- **守恒回填**（草稿省多少、池值加多少，总占用不变）在机制上避开 035 的触发条件。但 044 的载入瞬态压力窗（~5.1 GiB 滞留 → free=0）会因池值 +336~529 MiB 而同幅变深：PIN_PRE_EMPTY_CACHE 后 free 3313 → ~2780-3056 MiB，理论仍健康，**须实测复验 PIN 日志 free 轨迹**。
- 验收设计：同长度冷 prefill 对照（035 口径）3.4e9 基线臂 vs 守恒新池值臂，prefill 吞吐差异 <3% 判安全。

## 7. 阶段化计划（实施另行开工）

1. **阶段 1——mlp 1bit 探针 + 口径校准（核心第一步，约半天）**：`_gptq_regen.py` 族上加 mlp-only 1bit（g128 = 每组单 centroid，RTN sign 即可、无 GPTQ 优化空间，实现最小）生成探针臂 → B1 初筛（门 ≈0.42，§2）→ 过筛则一次生产 boot 测 /metrics 口径 acc + 8k/146k 探针（顺带校准 B1↔生产换算锚）。qkv/fc 保持 3bit 不动（用户裁定）。
2. **阶段 2——保守组合收口**：码本 2bit + o_proj/kernel_proj 1bit（−52 MiB，各自的接受率代价用 B1 分档实测，码本单独测以免与 mlp 1bit 混杂归因）。
3. **阶段 3——AutoRound 使能（条件触发）**：若 mlp 1bit 崩盘，AutoRound 原生层级量化（`_tmp_line_b/autoround_env` 现成）尝试 1.5bit 级替代（2bit + 更紧 group/对称裁剪）或在码本 2bit 上做接受率补偿。
4. **阶段 4——池值守恒上探**：最优配方 + E 轨合并，池值 3.4e9→3.74~3.92e9；035 复核实验（§6）+ PIN 压力窗复验 + L 上限实测 + needle 多深度。
5. **阶段 5——生产切换**：launcher 三行（`--speculative-config.model` 路径 + `--kv-cache-memory-bytes` + `--max-model-len`）+ **双 boot（新 checkpoint 路径变更会使编译缓存键失效 → 必然首编深塌）** + watchdog 阈值重标定 + grep 旧值。

## 8. 风险清单

- **R1 mlp 1bit / 码本 2bit 接受率崩盘**（概率高：1 centroid/组对 5 层累积误差敏感；码本质量直接打接受率；**用户已实证 qkv 维度「量化损失很大精度」——1bit 族风险同级警惕**）→ 阶段 2 失败则收益封顶 52 MiB，L 上限止步 ~180,544（仍 +10.7%）。
- **R0（新）用户裁定的推广风险**：o_proj/kernel_projection 1bit 与 mlp 1bit 是否触发同类「精度损失过大」须实测说话；若用户裁定推广到全部 1bit 维度，则只剩码本 2bit（30 MiB）一条路（L 上限 180,544，与保守档同阶——L 上限对 num_blocks 是 2-block 粒度阶梯，+30 与 +52 MiB 落同一格）。
- **R2 残谱 × 0.90 破 85 门**（86.7→~78）→ watchdog 重启兜底；阈值 105→100 重标定。
- **R3 035 机制若非纯「总占用」归因** → 阶段 4 prefill 崩复现 → 回退池值（保留 63 MiB 显存空闲不回填即回退，launcher 单行）。
- **R4 新 checkpoint = 编译缓存键失效** → 首编深塌必然发生 → 双 boot 流程（046 已固化）。
- **R5 旧臂格式兼容性** → 只用 gptq2c/gptq4c（现役 auto_round:auto_gptq）；q2mix 系先验证加载再说。
- R6 接受率的 boot 间漂移 ±1pp（043 B1 复测漂移 +1.2pp 同源风险）→ 生产口径判读须多请求聚合（/metrics 全量计数天然聚合）。
