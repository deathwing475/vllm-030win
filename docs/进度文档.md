## 二、任务板

- **T-perf（移植完成后执行）**：decode 性能优化——spec 管线 O(L) 每步开销定罪（100k 处带草稿比无草稿慢 2.7×）、短上下文 spec 步长 2.2× 压回 1.4×。证据包齐（步骤 006-008）。
- **阶段 2 必解缺口（步骤 011 新增，均带根因）**：
  1. **批 3**：humming int3 × torch.compile 不兼容（dynamo 追踪 humming_forward 的 compute_config 炸 json.loads）——0.29 底座 GSQ 只能 eager；0.27.1 overlay 生产跑 PIECEWISE ⇒ overlay 必带兼容垫片，搬批 3 时恢复；
  2. **批 3**：WNA16 内核分叉——0.29 清单 Marlin 在 Humming 前，int4 g64（embed/lm_head）走 Marlin、int3 走 Humming（旧栈全线 Humming）；禁 Marlin A/B 加载期 repack OOM ⇒ 恢复全线 Humming 需解决 repack 显存峰值；
  3. **批 4+5**：SM120 静态选 XQA decode 且上游 XQA spec 未接线 ⇒ 一切多 token 投机解码（dspark/DFlash2/MTP）在纯底座结构性不可用（capture 期炸 `xqa backend does not support cum_seq_lens_q`）。
- **锚点缺口**：A7 vision 131k/155k 仍挂账（不阻塞批 1/2）；A6/A8 已补采（`锚点数据包/smoke_s3_s6_20260926.json`）。
- **A5 115k 档 400**：错误体未捕获待查（不影响 100k 内锚）。
- **GSQ fp8 KV 实测单价**：42,810 B/token（GDN 状态同池，纯 full-attn 账低估 29%）——后续 GSQ 池值手算按此价。
- **回馈上游候选**：mapped_file Win32 移植、ops/utils 构建旗标修复 → SystemPanic/humming-windows PR。
