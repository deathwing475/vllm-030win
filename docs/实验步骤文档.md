## 步骤 023 — CPU 派发优化战役首胜：草稿图化解耦（decode −13.3%）（2026-09-26 深夜）

- **协议**：按步骤 022 靶点清单攻图外 CPU 派发；判定=e2e 步长（AOT 命中 boot 三连取中位，同产物复测排除胶水运气）+ 正确性门（needle 32k/chat/接受率带内）；实验 B 阴性也要记档。测量噪声口径：hit-boot 复测散布 ±1.3%。
- **操作**：
  1. **基线**（AOT 命中 boot）：e2e **31.53ms** p50 + trace 子段归属——三大发现：①`pin_memory` 347µs 是 prefill 期大块钉页（decode 期 7µs，**撤销该项**）②草稿前向（`Call CompiledFxGraph`）每调用含 6×apply_humming（572µs）+4×grouped_conv，**每步 ~3.7 次 ≈ 3.7ms/步 Python 胶水**③GDN 包装每调用有真实张量活（copy_×6/clone×3/index_put_×2）。
  2. **实验 B（阴性）**：splitting_ops 去 GDN 两变体（想把 48 次/步包装捕进 PIECEWISE 图）——**32k 输出塌缩**（"system of the system"重复风暴=GDN 状态/分支被图冻结错），立即回退。结论：GDN 算子不可简单入图，48 次/步是结构性成本，只能 wrapper 减脂（挂账）。
  3. **实验 C（✅ 胜）**：定位 `dflash/speculator.py:init_cudagraph_manager`——**草稿图模式被绑死在 target 模式上**（engine=PIECEWISE ⇒ 草稿直接 `NONE` 全 eager，注释原话「PIECEWISE cudagraphs are not supported for dflash」），而草稿的 `FULL_DECODE_ONLY` 图管理器是现成实现、与 target 图模式无关。修复=解耦（supports_full 且 engine 非 NONE 即用 FULL_DECODE_ONLY；双轨落地）。**风险天然低：草稿错了只掉接受率，target verify 兜底输出正确性**。
- **结果**：

  | 指标 | 基线 | 实验 C boot-1 | boot-2（同产物复测） |
  |---|---|---|---|
  | e2e 步长 p50 | 31.53ms | 27.29ms | **27.35ms（±0.2% 复现）** |
  | 接受率 | 0.72-0.74 | 0.70-0.74 | 0.68-0.74（带内） |
  | needle 32k | ✓ | ✓ 命中输出连贯 | — |
  | 吞吐 | ~77 tok/s | ~89 tok/s | **+15.5%** |

  草稿图捕获日志确认（`Capturing model for DFlash2 speculator... Graph capturing finished`，无「不支持 full graphs」警告=supports_full）；AOT 命中 3/3。降幅 4.2ms ≈ 预测的草稿胶水 3.7ms/步，机制吻合。
- **判定**：**CPU 派发优化战役首胜 ✅：decode 步长 31.53→27.35ms（−13.3%），输出正确性与接受率保持**。剩余靶点（挂账按预期收益排）：①GDN 包装张量活减脂（copy_/clone/contiguous 每调用，48×/步）②attention/kv_update 包装③apply_humming 派发单价（~95µs/次）④生成码快慢态差解剖。教训：①「图化」对无状态算子（humming GEMM）安全、对元数据分支算子（GDN）致命——入图实验必须过输出正确性门；②trace 子段归属能推翻表层归因（pin_memory 撤案）；③草稿/验证的正确性分工让图化实验风险不对称——先打风险低的。

## 步骤 022 — T-perf 诊断战役：平步长反常分离 + 溢出排除 + decode 步内剖 + AOT 缓存失效根因（2026-09-26 夜）

- **协议**（四问四验）：①步骤 018 平步长异常（stage0 31/31/33 vs anchor 33/50/98ms）三疑点（会话/请求路径/内容）分离；②用户观察「100k 尾段 util 跌 70%、短提示词 decode 也才 80% 没吃满」——溢出嫌疑按铁律判据实测（per-process Shared>0.1GB + 行为签名）；③torch profiler 步内剖定位 GPU 空转的空隙归属；④一切修复走 git + A/B/端到端验证（Q4 教训：不许多改合并后宣称修复）。
- **操作**：
  1. **工具口径对账 + 两侧数据解剖**：anchor_longctx（completions/英文 haystack/mt=256）vs stage0_ttft（chat/中文 wiki/mt=1024，复用 `_run_decode_bench`）。两侧 tail≈0、tok/delta≈2.1-2.6（delta=引擎步粒度，chunk≠token 坑排除）、指标各自自洽——差异真在引擎行为。
  2. **三疑点判别矩阵**（`tools/probe_tperf_matrix.py`，单 serve 会话逐因子拨动 + 逐 delta 时间戳 + /metrics 接受率差分）：32k 六臂（A=anchor 复刻/S=stage0 复刻/P 路径因子/C 路径因子/M mt 因子/A_rep 会话序）全臂 45.7-47.5ms p50——S 臂（stage0 精确复刻）45.7ms，30.6ms 平步长**未复现**；8k/100k 全臂 37-44ms 十段全平。**三疑点全灭，异常是实例（boot）级**。
  3. **长 decode 对照 + 溢出实测**（用户方案：短提示词先测本底再测 100k）：短提示词 4000tok = 36-38ms/步 vs 100k 4000tok = 37-38ms/步（十段全平）——decode 本底与 L 无关；gpu_mem_monitor 35 样本覆盖两次长 decode 全程：**python per-process Shared 488MB 一条平线（±0MB）**、adapter_shared 微降、行为签名阴性 ⇒ **非溢出**；GPU 时钟 decode 段 3000-3052MHz 满血、140-235W——70%/80% util 是 decode 阶段形态（prefill 99%→decode 72-80%）非降频非溢出。
  4. **torch profiler 步内剖**（`--profiler-config.profiler torch` scratch launcher + `/start_profile`/`/stop_profile`，trace 时间线双指针归因）：**GPU 内核并集 14.9ms/步 ≈ 权重读取地板**（27B 3bit ~12.5GB/960GB/s），步长其余=图外 CPU 派发——PIECEWISE splitting_ops 全在图外逐个派发：`qwen_gdn_attention_core_fused_norm_packed` 244µs/次×48、`unified_kv_cache_update` 329µs×21、`unified_attention_with_output` 226µs×21、CompiledFxGraph 调用 7.5ms/步、`apply_humming_linear` 136µs/次（批 3b custom-op 边界每调用 `to_str()` JSON 序列化）。**spec 理论收益 2.5×（摊薄权重读）实拿 1.27×（66 vs 无草稿 52 tok/s），一半被 CPU 派发吃掉**。
  5. **to_str 缓存修复**（humming.py 层内缓存 + humming_utils 收 str，双轨落地）——**A/B 被 boot 方差混淆**（同日不同 boot：修前 25.78 vs 修后 26.79ms），保留为代码卫生、不宣称收益。
  6. **boot 级方差追查**（25.8/26.8/36.9-44ms 多态）：池状态积累假说（100k 请求后复测 25.7ms 不慢）排除；AOT 产物审计（`audit_aot_cache.py` 带 op 注册加载 source_info 逐文件对账）→ `parallel_state.py` 内联 vs 磁盘**恰差 1 字节**；微观实验定机制：**`inspect.getsource` 对无尾换行文件补 `\n`、`open().read()` 不补，而 parallel_state.py 恰无尾换行** ⇒ 校验每 load 必败 ⇒ 每 boot「Source code has changed」重编译 backbone ⇒ inductor 逐次 autotune 生成码不同（`benchmark_combo_kernel=True`）⇒ decode 步长随 boot 漂移。
  7. **修复（底座 `3498ef1`）**：`_compute_code_hash_with_content` 尾换行规范化（单点收敛，历史产物立即可命中）。踩坑记档：①类型注解 `"LayerConfig" | str` 在 def 求值炸（整体字符串 `"LayerConfig | str"` 才对）②分析器 argv 未接硬编码旧 trace 白跑一轮。
- **结果**（关键数据）：

  | 项 | 数据 |
  |---|---|
  | 三疑点矩阵 32k 六臂 | 45.7-47.5ms p50 全臂一致；S 臂=stage0 精确复刻 45.7（原 30.6 平步长未复现） |
  | 长 decode 对照 | 短提示词 36-38ms / 100k 37-38ms/步（十段全平，与 L 无关） |
  | Shared 判据 | python 488MB 全程 ±0MB（35 样本含 100k prefill+decode）、adapter_shared 微降 ⇒ 非溢出 |
  | GPU 时钟/功耗 | decode 段 3000-3052MHz / 140-235W / util 72-80%；prefill 99-100% |
  | 步内剖 | GPU union 14.9ms/步（贴权重地板）；CPU 派发 gap 15.9ms/步（profiler 口径）+ 注解内段间空隙 |
  | to_str A/B | 25.78（修前）/26.79（修后）——boot 方差混淆，无净效应结论 |
  | AOT 审计 | parallel_state.py inline=+1 尾换行（94,358 vs 94,357 字符，前缀逐字相同） |
  | 修复后确定性 | **boot1/boot2 = 30.81/30.70ms p50（±0.4%）；AOT 产物 3/3 `Directly load`、零重编译；启动 60s** |

- **判定**：**四问全结**：①三疑点全灭——平步长异常=boot 级状态；②溢出排除（仪器背书），用户 70%/80% util 观察实体=decode 阶段 GPU 空转（CPU 派发缺口）+ 多流 duty 口径，方向正确并直接引出步内剖；③decode 本底不慢（贴权重读地板）但 **spec CPU 派发吃掉一半理论收益——T-perf 头号优化靶点**（GDN/attention/KV-update 包装、CompiledFxGraph、guard 同步嫌疑，挂账立项）；④**boot 级方差根因定案并修复**（AOT 缓存失效=尾换行非对称→每 boot 重编译→生成码漂移），修复后同产物步长确定 ±0.4%。**历史数据重注**：步骤 018 平步长/O(L) 异常与 A5 个案大概率同根（生成码方差），历史锚标注「boot 方差时代采集」；同配置不同产物 25.8 vs 30.8ms（快慢态差 ~16%）挂账待查（生成码差异解剖）。下一步：CPU 派发优化战役（预估步长 30.7→~20ms 空间）或阶段 3 甄选滚动。

## 步骤 021 — KV offload 崩溃（R8）定罪修复 + 回填生产（2026-09-26）

- **协议**：闭环用户头号待优化项（多轮对话依赖 offload 做前缀缓存 CPU 延伸）：定罪根因 → 修复（走 git）→ 崩溃复现探针转绿 → 生产回填 → 全量验收（含多轮前缀场景）。
- **操作**：
  1. **判别实验矩阵定罪**（独立锤测 `_C_cache_ops.swap_blocks_batch` 原语 + C++ 源码/cuda.h 文档比对）：LAUNCH_BLOCKING=1 全同步下完整 offload 负载全过（竞态/时序性质）→ 独立锤测复现（侧流批量 DMA + 算力并发）→ 逐格剥离混淆因素（描述符 GC、在飞覆写、批内重叠区间——批内相关拷贝按文档属未定义行为）后**不相交+串行化仍炸** → **完美相关性：默认流用例全活（C++ 自带逐条兜底在起作用）、非默认流用例全炸（cuMemcpyBatchAsync 快速路径）**。API 语义核对无误（9 参 failIdx 旧 ABI 在 cuda.h 真实存在、`attrsIdxs` 长度=numAttrs 语义正确）⇒ **驱动级缺陷：cuMemcpyBatchAsync 在非默认流上使用即毒化上下文**（CUDA 13.3 / RTX 50 / Windows）。0.30 树同域仅 blocks→chunks 重命名差异，无上游修复可收敛。
  2. **修复（底座 `d7cdb91`）**：`_custom_ops.swap_blocks_batch`（C++ 路径的单点收口）Windows 分支改 ctypes 直调 `cuMemcpyAsync` 逐条拷贝——复刻 C++ 兜底语义（任意粒度/对齐、保留流序与转存流水），triton loads 路径与 XPU 路径不动。原语级验证：此前致命模式（侧流+wait_stream+算力+持久缓冲）300 轮存活 + 拷贝内容逐字节校验通过。
  3. **复现探针转绿**：offload 开 / 无 blocking / 无 spec（原必炸配置）8k×2 全过 needle，二发 TTFT 4.66→1.50s（前缀命中）。
  4. **生产回填**：launcher 补回 `--kv-offloading-backend native --kv-offloading-size 8` 两行，分离式重启生产服务（全配置：spec+prefix+offload）。
- **结果**（生产全量验收全绿）：health/110000 ✓；chat+reasoning ✓（297 字符）；tool-call ✓（`{"city":"广州"}`）；needle 8k×2+32k×2 全中——**多轮场景实证：8k 二轮 TTFT 4.67→3.09s、32k 二轮 TTFT 21.04→3.11s（整段前缀经 offload 层秒回）**；prefix 命中 31,152/81,128；spec 接受率 haystack 0.574（带内）；8k 稳态 67-69 tok/s（A5 锚 57.5 之上）；32k 稳态 66-67；日志三行 + OffloadingConnector/CPUOffloadingSpec 在；**共享显存 per-process 0 MB 无溢出**。
- **判定**：**R8 ✅ 修复并回填——待优化项头名闭环**（用户多轮对话场景的 offload 保回来了，回退预案不变）。待优化项余 T-perf（升头名）+ A7 vision 锚。教训记档：①原语级独立锤测+逐格剥离混淆因素=驱动级定罪的正确姿势；②「默认流活/侧流炸」的相关性直接指认 C++ 兜底与快速路径的分野；③cuda.h 文档是 API 语义判官（`attrsIdxs` 长度=numAttrs 反直觉，勿凭签名猜）。
