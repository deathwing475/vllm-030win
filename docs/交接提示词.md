17. **⭐门控补丁的通用纪律（057 立）**：**改任何被模型/图编译引用的源文件都会改掉 AOT 编译缓存的键**（源码参与 hash）⇒ 部署后**第一次 boot 必然重编译且处在退化态**（057 实测同配置首 boot 146k 只有 **34.12** tok/s、8k 101-104，第二 boot 恢复 104-108）⇒ **一律双 boot 或走 `tools\prod_watchdog.ps1`，禁止拿单次冷 boot 判性能回归**。同理：**仓库↔venv 同步必须用 `tools/sync_venv.py`**（逐文件比内容 + **保留目标侧行尾**；本仓 `vllm/` 是 LF、venv 安装副本是 CRLF，纯字节比较会全树误报）。
18. **⭐重启时序纪律（057 新观察，建议进 watchdog）**：`kill_vllm_orphans.ps1` 之后**先轮询 `nvidia-smi --query-gpu=memory.used` 落回 <800 MiB 再起服**——057 实测「kill 后 5 s 就 boot」连续 **4 次全被挤**（38/68/64/322 MiB、8k 落 100-104 带），而「等到落回 ~124 MiB 再 boot」一次就干净（被挤 **0**、dedicated 15,497.8 / shared 8,298、8k 120-121）。与 049「boot 中途压力比 boot 前常驻贵得多（56 vs 111）」同族：旧引擎 VRAM 尚未被 WDDM 归还时起新引擎 = 在新 boot 的中途制造压力。
