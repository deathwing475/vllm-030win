## 关键机制（已定案，勿重新推导）

1. **mamba 显存账（045 定案）**：48 层 GDN ×（conv bf16 102,400 B + ssm **fp32** 3,145,728 B）/层/份 = 148.68 MiB/份；align 份数 = **2 + N(2) + ckpt(0) = 4（公式硬编码，不读 max_concurrent_batches）**。fp32 来源 = 模型 `config.json` 的 `mamba_ssm_dtype=float32`；**bf16 在 fused 白名单 `FUSED_GDN_STATE_DTYPES=(float32,bfloat16)` 内、fp16 不在（掉非 fused 路径）**。
2. **bf16 ssm 的容量联动（生产已生效，046 日志逐项复核）**：mamba page raw 3,248,128→1,675,264 → attn block 2832→1456 → 统一 page 1,677,312（pad 0.12%）→ `bytes_per_block`(G=8) 26,099,712→13,418,496 → num_blocks 130→253 → **L 上限 = 2·cdiv(L,1456)+28 ≤ 252 ⇒ 163,072**、容量 163,719。
3. **⭐首编深塌（新随机源，机制挂账）**：L/dtype 变更后的**第一次无缓存 boot**（AOT 重编译 ~145s）8k steady 16.8-18.7 tok/s（4/4）；**同配置第二 boot（缓存 ~61s）恢复 116-125**。深塌态投机在工作、无抢占 ⇒ 每步开销真实暴涨（~103ms），嫌疑 autotune-miss（#53436）。**046 实操结论：双 boot 的本质是「先有同配置编译缓存」——045 实验臂已预热，生产切换一次过；未来 L/dtype 变更若无缓存仍须双 boot（watchdog 判慢重启天然覆盖）**。历史统一：039「141,600 偏慢」、040 的 96-99 档可能均为首编/缓存 boot 之别。
4. **快慢态 + 钉快档（030/033/044）**：草稿权重 WDDM 掷骰子 → pin_shim 两遍搬移 + empty_cache；第二随机源（载入瞬态滞留池）→ 044 PIN 前置 gc+empty_cache 钉住，A/B 6 boot 全高带。**044 残谱预测命中（045）**：163k 缓存 boot 抽到 86.7 低带一次 ⇒ 83-99 残谱 = target 权重页 demote 成分（下一战役 target PIN ~26s）。

6. **容量（034/035/036/040）**：池值 3.4e9 硬上限（prefill 敏感，4.13× 慢）；`VLLM_KV_GROUP_SIZE=8`；容量公式 `blocks_per_req = cdiv(L,block)×cdiv(16,G) + 4·cdiv(48,G) + sw·cdiv(5,G) ≤ num_blocks − 1`（null block），`sw = cdiv(2047+2×mbt, block)+1`（**045 后 block=1456 时 sw=4；046 生产已用此口径**）。
